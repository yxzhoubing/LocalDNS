# FJH21 / UI 2026.10.28.3

修复 **FJH 内核发行标签被写死成 `fjg` 前缀**导致的两处失败：网页端 UI 升级对 `fjh21-ui-*` 一律判无效，一键安装器对 FJH21 完整包拒装。

- **网页升级接受 FJH21 发行版（PR #12）**：`ui_updater` 的 `TAG` 与前端 `upgradeTarget` 都写成 `fjg[a-z0-9]+-ui-v…`，`re.I` 只忽略大小写、`fjg` 仍是字面量，因此 `fjh21-ui-v2026.10.28.2` 不匹配：前端先报「发行版标签无效」，后端再报「请选择本项目的正式 UI 发行版」，面板升级只能失败。两处改为 `fj[a-z][a-z0-9]+-ui-v…`，与 `package_ui.py`、`install_localdns.py` 的内核版本形状一致（FJGOE → FJH21 不再假设第三位是 `G`）。
- **安装器接受 FJH21 完整包（PR #11）**：`install_localdns.py` 的 `backendVersion` 校验由 `FJG[A-Z0-9]+` 改为 `FJ[A-Z][A-Z0-9]+`，FJH21 一键安装包不再被判「安装包核心版本无效」；`install.sh` 的 `ENGINE_SHA256` 自举摘要同步更新。
- **跨核心护栏不变**：放开前缀只放宽第三位字母，后端仍比对 `tag.split('-ui-v')[0]` 与已装 `backendVersion`，前端仍比对 `release.backend`；FJGOE 设备升级 FJH21 界面依旧被拦截并提示走完整包迁移。
- **验证**：`test_ui_updater.py` 新增 FJH21 用例，跑完整升级事务（接受 `fjh21-ui-v…` 并成功、`fjgoe-ui-v…` 仍被核心比对拦住）；`ui-update.test.ts` 新增同核心放行与 `xjh21-` 前缀拒绝用例。`npm run check` 共 160 项通过；`test_oneclick_installer.py` 16 项、`test_package_ui.py` 15 项、`test_shared_ui.py` 6 项、`test_fjgli_upgrade.py` 7 项全部通过。

## 升级说明

本次只改工具与前端标签校验，**不涉及 DNS 内核、配置、规则与上游**：

1. 已在 FJH21 上的设备可直接用网页端「检查更新」升级界面，或运行更新包里的 `install-ui.sh`；无需重启 DNS。
2. 本版首次安装前，若设备上运行的是 2026.10.28.2 及更早的 `ui-updater`，其自身仍是旧的 `fjg` 正则，无法自举升级：请先用完整包或更新包里的 `ui-updater/install_ui_updater.py` 覆盖一次升级服务，之后的版本即可在面板内直接升级。
3. FJGOE 及更早内核请勿直接升级本界面包，仍按 [更新指南](../FJGLI_UPGRADE.md) 使用完整包迁移。

## 说明

`tools/install-ui.sh` 中的跨核心护栏仍只列举 `FJGLI` / `FJGOE`，未加入 `FJH21`；该脚本为旧版 UI 安装路径，且此处是「放行」而非「拦截」，语义不同，暂不随本版调整。
