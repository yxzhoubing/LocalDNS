# FJH50 / UI 2026.10.29.5

响应延迟卡片合并 PR 原型与本地图表内核：页签 4 → 2、真实采样曲线、KPI 状态条与整卡报警态。

## 变化

- **页签 4 → 2**：「延迟与异常」「请求量与缓存命中率」。`平均延迟` 与「延迟与异常」是同一份上游延迟数据（`responseSum / responseCount`），`缓存命中率` 并入请求量页签的右轴，两者都改为内部隐藏指标，不再单独占页签。
- **KPI 状态条**：解析健康（状态点 + `正常` / `N 失败 · M 慢查`，有失败时可点击跳转日志）、上游竞速、平均响应、P95 / 最大耗时四项一行，取代原先四个平铺数字。
- **真实曲线**：`anomalyChart()` 里写死的 12 点折线换成按采样绘制的曲线；Y 轴由 `axisCeiling(max × 1.15)` 自适应（不再固定 0/37/150/600）；100ms 慢查询阈值线只在坐标轴够得到时出现；峰值改为圆点 + 短引线 + 圆角标签；断采不连线。
- **请求量页签**：请求量改为柱状，缓存命中率走右轴折线（0/50/100%），图例移到 HTML 层。
- **整卡报警态**：有失败或慢查时卡片边框与光晕变红，状态点脉冲。
- **移除**：原型里的「模拟异常」演示开关、无数据源的「含缓存整体均值」曲线。

## 已知说明

延迟序列只在**两次采样之间确实有上游应答**时才产生：`record()` 需要上游 `_sum`/`_count` 前后一致且计数增长，空闲区间按设计留空。因此页面首次打开后需要至少两个真实 5 秒采样（约 10 秒）曲线才会出现。

用 headless 的 `--virtual-time-budget` 截图时，多个 5 秒轮询会被压缩进约 1 秒真实时间，计数器不变，`delta_count = 0`，曲线始终为空 —— 这是截图方式导致的，不是渲染缺陷。
