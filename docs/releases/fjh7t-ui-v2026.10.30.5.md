# FJH7T / UI 2026.10.30.5

分流页的名单分组页签重排：组名从「和页签并排的灰字」改成「页签上方的小标题」，三个组从两行收成一行，整条菜单比改前还矮 28px。

## 背景

「规则 → 名单管理」上方那条菜单把 12 个名单分成三组，但组名（核心分流 / 解析控制 / PCDN 抑制）和页签（白名单 / 强制 RealIP …）是同一个视觉层级：页签是描边胶囊，组名只是加粗一点的灰字。结果组名看起来像「漏了边框的页签」，组间那根竖线又像把一行切成了三段；窗口窄一点时第二行还以「PCDN 抑制」开头，更像一个普通页签。

## 三种改法与实测

同一份真实样式、同一段文案，只换 `rules.css` 末尾那一段，在 1100px 视口量出来：

| 方案 | 组名怎么放 | 页签 | 菜单高度 | 占几行 |
|---|---|---|---|---|
| 改前 | 与页签并排的灰字 | 各自描边胶囊 | 95px | 2 |
| B 轨道式 | 轨道外 | 整组装进分段控件轨道 | 101px | 2 |
| **C 两行式（采用）** | **抬到页签上方** | 保持描边胶囊 | **67px** | **1** |
| D 竖条式 | 加强调色竖条 | 保持描边胶囊 | 87px | 2 |

选 C 的两个理由，都与最初的直觉相反：

- **它反而最矮**。组名从「横向占位」变成「纵向分层」之后，三组能在同一行放下，总高度比改前少 28px；B 和 D 仍是两行。
- **它不引入第二种控件形态**。B 的轨道与右上角「名单管理 / 广告拦截 / 在线分流」是同一种分段控件，但那三个是切换整个视图，这里的组内页签只是换名单——同形不同义容易误读。

D 改动最小，但组名仍与页签并排、仍在同一行里比颜色深浅，没跳出原来的思路。

## 适配

| 位置 | 改动 |
|---|---|
| `frontend/src/styles/features/rules.css` | 末尾的分组样式整段替换：`.rule-menu` 改 `align-items:flex-start`、组间距 12/26px；`.rule-menu-group` 改纵向排列（组名在上、页签在下）；`.rule-menu-group-label` 改 10.5px 半粗、字距 .14em、`--text-3`；`.rule-menu-group-items` 去掉轨道底色与描边；页签恢复各自的 `--glass-pill` 描边胶囊，选中态保持强调色文字 |

页面结构没动，`index.js` 不用改——组名与页签的 DOM 层级本来就是分开的，只是之前被排成了一行。

**踩到的坑**：这段样式必须带 `body[data-console-route="rules"]` 前缀，并且放在 console 层之后。构建时的 `@csstools/postcss-cascade-layers` 会给 console 层的 `body[data-console-route="rules"] …` 规则插上十几层 `:not(#\#)` 提升权重，裸类名（哪怕写在文件末尾）压不住它们——这也是上一版「改了没生效」的原因。用同样的前缀 + 更靠后，才能稳定覆盖。

## 效果

- 三组并排一行，组名是独立的小标题，不会再被当成页签。
- 菜单从 95px 降到 67px，名单编辑区多出近 30px 可视高度。
- 深色皮肤（流光毛玻璃）下同样成立：组名用 `--text-3`，页签仍是各自描边，选中项仍是最亮的那颗。

## 验证

- `npm run check` 全绿：21 个测试文件 173 项单测、ESLint、`tsc --noEmit`、构建一致性校验、字体子集检查。
- 三种方案都用**真实构建产物**渲染对比（不是手写原型）：1100px 视口量菜单高度，浅色与深色各出一版。

## 升级说明

- **UI 更新包**：只替换界面资源，不动内核、配置、规则与上游，无需重启 DNS；安装后刷新页面即可。安装脚本按 `ui/version.json` 的 `backendVersion` 做同核心校验，要求内核已是 **FJH7T**。
- **完整包**：含 FJH7T 内核与干净的默认配置，用于全新安装或整机替换。
- 若某个安装把「规则」页的菜单做了自定义样式覆盖（`ui/custom/`），升级后仍以自定义为准。
