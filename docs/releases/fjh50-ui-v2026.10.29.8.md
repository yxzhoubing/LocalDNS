# FJH50 / UI 2026.10.29.8

修正 2026.10.29.7 延迟曲线的两个统计缺陷。

## 问题

- **采样点被整体过滤**：`summary()` 要求 `elapsed > 0`，但延迟已改为上游 p50 仪表值，与采样间隔无关。记录时被判为「无效间隔」的样本（`elapsed = 0`）被整条丢弃，曲线因此断成碎片。
- **加权取错字段**：`for (const [key, , count] of latency)` 里的 `latency` 每项是 `[key, {sum, count}]`，第三个元素恒为 `undefined`，`count > 0` 永远不成立，计数加权退化成等权平均。

## 修正

- 延迟序列不再要求 `elapsed > 0`（`baseMetric === 'latency'` 时跳过该条件），其余指标维持原样。
- 改为 `const count = row?.count ?? 0`，按各上游的响应计数加权。

## 显示

- Y 轴上限为奇数时只画首尾刻度，不再出现 `13`（12.5 四舍五入）这类刻度。
- 100ms 阈值标签与末尾数值标签重叠时自动隐藏。

## 验证

- `npm run build` / `typecheck` / 161 项单测 / `eslint --max-warnings 0` / `verify:generated` 全部通过。
- 生产环境实测：曲线连续，无碎片；轴刻度为 0 / 25。

## 升级说明

仅前端改动，DNS 内核、配置、规则与上游不变；更新 UI 无需重启 DNS。
