# FJH50 / UI 2026.10.30.1

修复 2026.10.29.9 概览页的渲染回归：KPI 卡图标撑满整张卡片，顶栏连接状态显示为报错文本。

## 问题

2026.10.29.9 的概览去重删掉了服务摘要里的「已连接」徽章（`<span class="service-connection">`），但 `frontend/src/features/shell/interface.js` 的 `connection()` 仍在无条件写它的文案：

```js
$('.service-connection', health).textContent = connected === null ? '连接中' : connected ? '已连接' : '已断开';
```

元素已不存在，这行抛出 `TypeError: Cannot set properties of null (setting 'textContent')`。而 `connection()` 正是 `apply()` 中 `overview()` 之前的一步，异常把后续整条渲染增强链截断，造成两个可见症状：

- **KPI 卡图标巨大**：`overview()` 没跑，卡片外层拿不到 `.console-kpi` 类，而 `.console-kpi .sk-top > svg { width: 15px; height: 15px }` 是唯一的图标尺寸约束，SVG 于是退回默认尺寸撑满卡片；同一条链上的 `.sk-chart` 火花线与数字字体也一并失效。
- **顶栏显示报错**：异常经全局 `unhandledrejection` 兜底弹出「操作失败」提示，同时连接状态被写成 `Cannot set properties of null …`，状态灯转为断开。

## 修复

`connection()` 改为先取元素再判空，徽章缺失时跳过：

```js
const badge = $('.service-connection', health);
if (badge) badge.textContent = connected === null ? '连接中' : connected ? '已连接' : '已断开';
```

徽章的移除是 2026.10.29.9 有意为之（概览去重），因此这里不恢复元素，只让代码容忍它不存在。

## 验证

- 新增 `frontend/tests/shell-connection.test.ts`：对旧实现精确复现 `TypeError: Cannot set properties of null (setting 'textContent')`，对修复后通过；同时覆盖徽章存在时仍同步文案的分支。
- `npm run check` 全部通过（20 个测试文件 167 项单测）。
- 生产环境用无头浏览器抓取渲染后的 DOM 复核：`.console-kpi` 由 0 个恢复为 6 个，页面不再出现「操作失败」提示。

## 升级说明

仅前端资源改动，DNS 内核、配置、规则与上游不变；更新 UI 无需重启 DNS。
