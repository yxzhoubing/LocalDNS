# DNS 趋势与 24 小时本机历史 · 2026-10-20

## 实施

- 基于现有玻璃 / 羊皮纸视觉，改为 DNS 趋势，单独切换 QPS、主缓存命中率、上游平均延迟；每种指标使用正确单位和加权分母。
- 默认 1 小时，提供 15 分钟 / 1 小时 / 6 小时 / 24 小时。浏览器每 5 秒读取一次既有指标，不增加接口请求频率或安装服务器采样。
- IndexedDB 按 API 地址保存原始计数，每个 5 秒时段只保留最新的一条，增量写入并删除过期记录。刷新恢复；读取或写入失败时提示并提供临时采样。
- 核心重启保留旧历史；计数回退、页面重新进入、可见性恢复和长期断采建立新基线，已暂停期间不补造请求量或曲线。
- 最多约 480 个有效汇总点，额外插入断采标记；区间统计保留原始峰值，细线展示汇总区间峰值，支持悬停、触摸和键盘查询。

## 自动与浏览器验证

- Vite 构建、类型检查、89 项 Vitest、ESLint 和源码指纹 / 干净重建一致性验证通过。
- `test_traffic.cjs` 验证原有吞吐统计、三种指标的实际增量及加权均值、缺失数据、无请求、核心与上游重置、24 小时保留、峰值汇总和显式暂停边界的存储往返。
- `test_traffic_storage.cjs` 使用 IndexedDB 实现验证跨实例恢复、来源隔离、同槽较新数据、跨来源过期清理、拒绝存储。
- `verify_dns_trends.cjs` 使用真实浏览器 IndexedDB，注入约 17,280 条隔离历史，验证刷新恢复、四个范围、单位切换、图表点数、峰值、方向键、手机点选、断网重试保留曲线，以及存储禁用时继续采样。
- 浏览器共检查两种皮肤 × 深浅主题 × 1440 / 390 / 320px 的 12 组布局，控制区均未越界，手机按钮至少 44px，页面无横向溢出；无页面异常、无后端写请求。报告与截图在忽略的 `dist/dns-trends-verification/`。
- Impeccable 检测仅提示既有 `overview.css:129` 中拓扑进度条的 `transition: width`，该处未在本次改动中修改；本次新控件没有新增该警告。已人工复核桌面浅色与手机深色截图。

## 范围与限制

未添加 SERVFAIL 曲线：当前计数不能可靠地区分该失败类型。上游平均延迟与保留日志的总体平均响应不是同一口径，界面已注明。

历史只属于当前浏览器与 API 地址；关闭网页、离开概览、后台休眠或清除站点数据后无法补回未采样的时段。未宣称已积累真实全天历史，测试中的全天记录均为隔离夹具。

本次只部署静态 UI，不改动或重启 DNS 核心和 9100 服务；未单独发布 GitHub Release，正式版号保持原值。通过构建哈希与 `build-meta.json` 指纹区分本次构建。
